## Findings that change how earlier results should be read

**Latent relL2 is badly nonlinear as a quality proxy.** 0.039 → FID parity with fp16; 0.238 → 16.4;
0.456 → 200. It understated MoDiff at W8A8 and overstated it at W4A4. Any W4A4 quality claim in this
project derived from relL2 needs re-reading.

**MoDiff's per-step deficit is mostly launch cost, not â/ô memory traffic.** The batch sweep shows
the deficit *falling* in absolute terms as batch grows (+8.09 ms/step at batch 32 → +2.93 at 64),
with a regime change between 32 and 64:

| batch | 8 | 16 | 32 | 64 | 128 |
|---|---:|---:|---:|---:|---:|
| i8 MoDiff / i8 base | 0.691 | 0.722 | 0.727 | **0.927** | 0.941 |
| i4 MoDiff / i4 base | 0.666 | 0.739 | 0.775 | **0.919** | 0.935 |

A cost that shrinks as work grows is not traffic. MoDiff adds three launches per layer per step
(`gn_stats_partials`, `gn_stats_reduce`, `gn_delta_absmax`); below batch 64 they add full latency,
above it only marginal occupancy. Corroborated by `int4_baseline` being *slower* than
`int8_baseline` at batch ≤32 and faster at 128 — int4 issues ~2× the launches.

This **re-ranks the optimisation list**: fusing the three GN-chain launches now looks more promising
than an int8 â/ô cache, which targets traffic. "~0.94×" is a batch-128 property, not a property of
MoDiff — at batch ≤32 it is 0.67–0.73×.

**The checkpoint is real.** `models/ldm/lsun_churches256/model.ckpt` is 2.69 GB / 1307 state_dict
entries since 2026-08-04. The "856-byte stub, randomly initialised" line inherited from the 08-01
report is false for everything measured since, and was corrected in the MoDiff report.

## Things that cost time this session, recorded so they don't repeat

- **Don't run a second CUDA process during a long generation run.** A concurrent FID job holding
  1.8 GiB OOM'd the VAE decode and cost ~25 minutes.
- **Background launches need absolute paths.** The shell's cwd resets between tool calls; a relative
  log redirect silently sent a job's output nowhere and it never started — indistinguishable from
  "still running".
- **Unpaired single-seed A/Bs are worthless here.** Run-to-run relL2 varies 10–30% at batch 8. Two
  wrong conclusions this session came from that; both were caught by checking a control that the
  change could not possibly affect.
- **A metric proxy is not the objective.** Weight-reconstruction error fell 31%, end-to-end error
  fell 7.5%.
